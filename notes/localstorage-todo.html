用 localStorage 保存 JavaScript 待办清单｜刷新后恢复任务

待办清单刷新后消失，可以在任务变化时保存数组，再在页面加载时恢复。跟着这篇教程把文字和完成状态一起写入 localStorage，并用刷新和开发者工具验证。

先区分任务数据与当前视图

待办清单把任务保存在 tasks 数组中；分类、完成状态和搜索词只决定当前显示哪些任务。这样切换筛选时不会把未显示的任务从存储中移除。

每项任务包含编号、文字、完成状态和分类。本站用 sulin.tasks.v2 作为存储键名，使清单数据与页面动态偏好等其他设置分开。

准备好 从零制作待办清单的 HTML 和 JavaScript，再在同一份练习代码上加入下面的保存和恢复步骤。完整工具的筛选与撤销见 JavaScript 待办清单项目案例。

在第一篇的代码上加保存和恢复

在 index.html 的 <ul id="task-list"></ul> 后加入下面一行，用来显示保存状态。

<p id="storage-status" role="status"></p>

在 todo.js 里，把 let tasks = []; 和紧跟着的 updateTasks() 一起替换为下面这段。文件中的 render()、表单事件和末尾的 render(); 都继续使用。

const storageKey = 'todo-tutorial.tasks.v1';
const storageStatus = document.querySelector('#storage-status');
let tasks = loadTasks();

function loadTasks() {
  try {
    const raw = localStorage.getItem(storageKey);
    if (raw === null) return [];

    const saved = JSON.parse(raw);
    if (!Array.isArray(saved) || !saved.every(task =>
      task && typeof task.id === 'string' &&
      typeof task.text === 'string' && task.text.trim() &&
      typeof task.done === 'boolean'
    )) {
      throw new Error('任务数据格式不正确');
    }

    return saved;
  } catch {
    storageStatus.textContent = '读取任务失败，当前显示空清单。';
    return [];
  }
}

function updateTasks(nextTasks) {
  tasks = nextTasks;

  try {
    localStorage.setItem(storageKey, JSON.stringify(tasks));
    storageStatus.textContent = '已保存在当前浏览器。';
  } catch {
    storageStatus.textContent = '保存失败，刷新后可能丢失本次修改。';
  }

  render();
}

脚本先执行 loadTasks()，再由末尾的 render() 显示恢复的任务。添加、勾选和删除都会经过 updateTasks()，所以这三种修改都会尝试保存。

读取时检查数组和字段，遇到损坏的 JSON 或格式错误时显示提示。写入失败时，本次修改仍会显示在页面上，刷新后可能丢失。

用刷新验证保存是否生效

  1. 用第一篇的本地地址打开练习页，添加「阅读文章」和「整理笔记」。
  2. 勾选「阅读文章」，刷新页面。应看到两条任务都还在，且只有「阅读文章」保持勾选。
  3. 删除「整理笔记」，再刷新一次。应只剩「阅读文章」。
  4. 在 Chrome 按 F12，打开「应用（Application）」里的「本地存储（Local Storage）」。选中当前练习地址，在 todo-tutorial.tasks.v1 的值里查看任务文字和 done 状态。Chrome 开发者工具说明

练习页用 todo-tutorial.tasks.v1 保存数据。苏林作品集的完整项目用 sulin.tasks.v2，另外处理了重复编号、分类和字数限制。查看待办清单源码

保存：把任务数组转成字符串

localStorage 存储字符串，因此保存前使用 JSON.stringify()。下面是项目中保存函数的核心写法：

function save() {
  try {
    localStorage.setItem(storageKey, JSON.stringify(tasks));
    storageOK = true;
  } catch {
    storageOK = false;
  }
  byId('storage-state').textContent = storageOK
    ? '自动保存在当前浏览器'
    : '当前无法保存，刷新后任务会清空';
}

任务添加、编辑、完成、删除和撤销后都会调用保存函数。筛选与搜索只改变显示，不需要重新保存任务数据。

恢复：解析之后还要检查内容

页面启动时读取字符串，缺少保存记录时以空数组开始。JSON 解析可能失败，解析成功的值也不一定具有正确的任务结构。

const stored = JSON.parse(
  localStorage.getItem(storageKey) || '[]'
);

if (Array.isArray(stored)) {
  // 项目中继续检查字段、文字长度与重复编号。
}

完整源码会检查编号和文字类型，过滤空文字与重复编号，最多恢复 500 项任务，并把不认识的分类归入学习。读取存储不会自动执行其中的文字。

显示输入与处理失败

页面通过 textContent 显示任务文字，而不是把输入拼接成 HTML。保存内容也需要与新输入一样谨慎处理，不能因为来自本地存储就直接信任。

浏览器可能限制存储访问，写入也可能失败，因此读取和写入分别捕获异常，并在界面上显示当前保存状态。用户仍可操作清单，但需要知道哪些内容尚未成功保存。

localStorage 的边界

数据属于当前站点的来源，并保存在当前浏览器中。它不是云端账户，不提供跨设备同步；清理站点数据也可能移除任务。同一浏览器其他标签页的更新，目前通过提示刷新来处理。

本文讨论的是小型个人工具的存储方式。它不替代备份、账户系统或并发数据同步。
