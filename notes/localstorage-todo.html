JavaScript 待办清单如何用 localStorage 保存数据

先区分任务数据与当前视图

待办清单把任务保存在 tasks 数组中；分类、完成状态和搜索词只决定当前显示哪些任务。这样切换筛选时不会把未显示的任务从存储中移除。

每项任务包含编号、文字、完成状态和分类。本站用 sulin.tasks.v2 作为存储键名，使清单数据与页面动态偏好等其他设置分开。

保存：把任务数组转成字符串

localStorage 存储字符串，因此保存前使用 JSON.stringify()。下面是项目中保存函数的核心写法：

function save() {
  try {
    localStorage.setItem(storageKey, JSON.stringify(tasks));
    storageOK = true;
  } catch {
    storageOK = false;
  }
  byId('storage-state').textContent = storageOK
    ? '自动保存在当前浏览器'
    : '当前无法保存，刷新后任务会清空';
}

任务添加、编辑、完成、删除和撤销后都会调用保存函数。筛选与搜索只改变显示，不需要重新保存任务数据。

恢复：解析之后还要检查内容

页面启动时读取字符串，缺少保存记录时以空数组开始。JSON 解析可能失败，解析成功的值也不一定具有正确的任务结构。

const stored = JSON.parse(
  localStorage.getItem(storageKey) || '[]'
);

if (Array.isArray(stored)) {
  // 项目中继续检查字段、文字长度与重复编号。
}

完整源码会检查编号和文字类型，过滤空文字与重复编号，最多恢复 500 项任务，并把不认识的分类归入学习。读取存储不会自动执行其中的文字。

显示输入与处理失败

页面通过 textContent 显示任务文字，而不是把输入拼接成 HTML。保存内容也需要与新输入一样谨慎处理，不能因为来自本地存储就直接信任。

浏览器可能限制存储访问，写入也可能失败，因此读取和写入分别捕获异常，并在界面上显示当前保存状态。用户仍可操作清单，但需要知道哪些内容尚未成功保存。

localStorage 的边界

数据属于当前站点的来源，并保存在当前浏览器中。它不是云端账户，不提供跨设备同步；清理站点数据也可能移除任务。同一浏览器其他标签页的更新，目前通过提示刷新来处理。

本文讨论的是小型个人工具的存储方式。它不替代备份、账户系统或并发数据同步。
