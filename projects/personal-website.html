网站要展示什么

这个网站围绕三个问题展开：苏林正在学习什么、已经做出了哪些作品，以及访问者在哪里可以体验页面和查看代码。首页集中展示个人网站、待办清单与视觉实验，项目详情负责说明功能和实现过程。

内容以个人前端学习为出发点。每个案例提供技术选择、交互方式和源码入口，便于从画面继续了解实现过程。

用语义结构组织页面

首页使用 header、nav、main、section、article 与 footer 组织内容。一个清楚的主标题介绍网站主题，分区标题分别说明作品、技能、实践笔记和交流入口。

作品卡片通过普通链接进入独立案例页。环形画廊保留快速预览弹窗；需要阅读完整介绍时，可以继续打开相应案例。正文和链接直接保存在 HTML 中，关闭 JavaScript 后仍可阅读主要内容。

让作品列表适配桌面与手机

桌面端作品区使用两列 Grid，视觉实验跨两列展示。屏幕宽度不超过 760px 时，作品列表改为单列，导航可以展开，环形画廊改为横向滑动。手机端优先保证阅读顺序与操作空间。

手机仍需检查较长中文标题、按钮换行、图片裁切和页面横向溢出。具体的 Grid 写法记录在 响应式作品列表实践笔记 中。

为交互保留清楚的控制方式

原生 JavaScript 负责作品分类、技能选项卡、移动导航、弹窗和动态控制。选项卡支持方向键、Home 和 End；弹窗关闭后把焦点交还给触发按钮。页面也会读取系统减少动态效果的偏好。

桌面环形画廊通过三角函数计算卡片位置，只在画廊可见、页面处于前台且没有暂停时更新位置。悬停与键盘聚焦也会暂停环绕。查看环形画廊的实现说明。

图片与页面信息如何维护

首屏和作品预览提供多个宽度的 WebP 图片，浏览器通过 srcset 与 sizes 选择资源；首屏图片优先加载，非首屏图片延迟加载。图片保留尺寸信息，减少加载时的布局变化。

每个页面有对应的标题、描述和 canonical 地址。站点地图列出公开页面，项目介绍和实践笔记通过首页互相连接。后续可以在 Search Console 中核对实际抓取与查询表现，再根据真实数据调整内容。

网站无需构建步骤，文件可以直接由静态服务器提供。返回苏林的前端作品集首页，或 查看完整 GitHub 仓库。
